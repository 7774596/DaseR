# 内存 / SSD 数据链路简化：阶段报告

本阶段完成了读写依赖和缓冲区生命周期的集中管理，并补了两处调度、
资源释放优化。H800 实测能看到 **packed 写入的局部收益**，但读取和 raw
写入仍有性能退化，暂时不适合按“全面提速、无回退”合并。本 PR 保持 Draft。

端到端首轮已完成 5/8 组，共 10/16 个并发配置；第 6 组因其他 GPU 任务
进入被保护机制中止，原进程实际退出码为 1。已完成结果和失败记录均保留，
剩余 3 组正在同一张 H800 上完整补跑，不能把当前状态写成全套通过。

## 这次解决了什么

- **读路径集中等待依赖。** 普通 load、grouped load、prefetch 统一处理待完成
  写入和共享 promotion。共享写入失败时，每个依赖它的 reader 都能收到失败；
  reader 取消不会取消其他请求仍在使用的 IO。
- **写路径统一生命周期。** raw / packed 共用快照、提交与完成管理。取消或
  出错时仍等待实际 IO / CUDA copy 结束，再释放对应缓冲区；drain 时及时回收
  已完成的 H2D copy，避免不必要的等待。
- **减少单个完成任务的调度开销。** 只有一个 future 时直接 shield 并等待，
  避免创建单元素 gather；GPU→pinned 快照直接提交 executor，同时保留
  contextvars 传播和取消时的缓冲区保护。
- **解除关闭后的引用环。** L1 close 后清除绑定 transfer 的 pinning callback。
  单独的 CPU 所有权实验中，关闭并删除 100 个实例后，显式 GC 前仍被保留的
  实例由 100 个降到 0 个。这证明引用环被解除，**没有测得 RSS 或显存下降**。
- **修正评测覆盖口径。** 同一 family wave 的共享 prefix 可以只读取一个
  物理源；分别校验每 wave 的源数据覆盖及精确的 query / hit token 数，
  不再要求物理读取量随并发数重复增长。输出一致性和 SSD 覆盖门槛保持不变。

GPU worker 与 server 的职责、IPC 接口及启动时固定的 backend 选择保持原有约束。
这轮主要减少重复状态处理和调度，没有去掉每个 GPU 目标必要的数据复制。

## 实验怎么做

使用同一张 NVIDIA H800、NVMe / io_uring，Python 3.10.20、PyTorch 2.13.0+cu129、
vLLM 0.30.0+cu129；模型为 Meta-Llama-3.1-8B。

每组先跑 ABBA × 2，形成 4 对按时间相邻的 A/B。预先规定：任一 p50 比值
大于 1.05、p95 大于 1.10，或吞吐小于 0.95，就完整复测该组一次，最终保留
全部 8 对。不会挑选快的结果，也不会一直重跑到通过。以下比值是配对比值的中位数，
不是统计显著性结论；达到门槛也不代表每个指标都变快。

微基准覆盖 4 KiB / 256 KiB / 4 MiB / 16 MiB，并发 1 / 4 / 16，
每个进程每个配置预热 3 波、测量 30 波。读取覆盖重复、交叠、独立、混合命中、
全命中及小 L1 场景，BIP 和计数探针分别开关；写入覆盖 raw / packed，BIP 开启，
计数探针分别开关。违反 direct-IO 对齐条件的预设配置明确跳过，不修改尺寸凑结果。

端到端覆盖 raw / packed、预取 0 / 2、生成 1 / 128 tokens、并发 4 / 16。
使用 8 个 family、2048-token prefix、128-token suffix，L1 为 512 MiB，L2 为
8 GiB。warm 阶段启用 skip-save，测的是读取与生成；冷启动播种及 drain 验证
写入正确性，持续写入性能由写入微基准衡量。

## 目前结果

| 实验 | 已完成范围 | 达到性能门槛 | 未达到门槛 |
| --- | --- | ---: | ---: |
| 读取微基准及规定复测 | 264 个有效配置，另有 24 个预设跳过 | 238 | 26 |
| 写入微基准及规定复测 | 132 个有效配置，另有 12 个预设跳过 | 125 | 7 |
| 端到端首轮 | 5/8 组，即 10/16 个并发配置 | 已完成的 10 个 | 完整矩阵待补齐 |

写入的 7 个退化配置全部是 raw，packed 的 66 个配置均达到门槛。
下面是 **256 KiB、并发 16、BIP 开启、关闭计数探针** 的三个 packed 场景：

| 请求范围 | 写入接受 p50 | 完成 p50 | 完成 p95 | 逻辑吞吐 |
| --- | ---: | ---: | ---: | ---: |
| same：请求相同范围 | -11.7% | -1.4% | -3.5% | +1.0% |
| overlap：部分交叠 | -7.1% | -4.5% | -5.9% | +6.1% |
| disjoint：范围独立 | -9.5% | -7.4% | -7.8% | +7.8% |

这是指定场景的局部收益。同一切片下 raw 完成 p50 反而增加约 1.5%–3.5%，
只是仍在预设门槛内。不能用上表替代完整矩阵。

读取退化以全命中和小 L1 场景为主。BIP 开启、关闭计数探针时仍有 5 个退化配置，
例如全命中 256 KiB / 并发 1 的 p95 增加约 32.9%，吞吐下降约 7.4%。
raw 写入的退化包含大块并发写的接受延迟及尾延迟；这些问题均保留在结果中。

已完成的端到端 5 组没有触发复测门槛，整体接近持平，尚无稳定模型级加速证据。
例如 raw / 关闭预取 / 生成 1 token / 并发 4 的 TTFT p50 增加 4.82%，
p95 降低 9.30%，吞吐增加 1.93%；不同指标方向并不一致。
